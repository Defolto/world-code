# Уровни: шпаргалка

Всё, что нужно знать, чтобы написать уровень, не открывая симулятор.
Если что-то здесь расходится с кодом — прав код, а файл поправить.

## Где что лежит

| Что | Где |
|---|---|
| Уровни | `content/levels/<id>.yaml`, имя файла = `id` |
| Схема и проверка формата | `tools/level_schema.py` (Pydantic, `extra="forbid"` — лишний ключ = ошибка) |
| Правила мира | `simulator/world.py` (`World`, `Hero`, `DEFAULT_OBJECTS`, `DIRS`) |
| Прогон и исход | `simulator/runner.py` (`run(source, level) -> лог`) |
| Автосолвер (гейт качества) | `simulator/tests/test_levels.py` |
| Доставка в браузер | плагин `levels-from-yaml` в `frontend/vite.config.ts`: вырезает `solution`, `hints`; правка YAML в деве — перезагрузка страницы |
| Отрисовка карты | `frontend/src/components/LevelScene.tsx` (умеет: wall/floor, flag, ворота, предметы, яму `jumpable`, паутину `crawlable`) |
| Порядок в UI | `Play.tsx`: сортировка по `lesson`, потом по `id` |
| Превью плитками | `backend/.venv/Scripts/python tools/tiles.py preview dungeon <каталог>` |

## Правила мира (как реализовано, а не как задумано)

- Координаты `[x, y]`, начало в левом верхнем углу, `y` вниз. Первая строка каждого файла — комментарий об этом.
- Герой стартует лицом вправо. Каждая команда — один тик, **включая шаг в стену**: он даёт событие `blocked`, а не ошибку Python.
- `hero.move_right(3)` — три шага одной строкой: каждый шаг — свой кадр, тик и единица энергии; серия обрывается на первом неудачном (стена, нет сил), команда возвращает `True`, только если прошли все. Аргумент — целое ≥ 1, иначе человеческая ошибка. Уровень-практика — start-10.
- За краем карты — стена. Клетка без записи в legend — ошибка.
- `DEFAULT_OBJECTS`: `floor`, `wall` (blocking), `flag` (проходим) — описывать в `objects` не нужно. Любой другой вид надо описать в `objects`. Флаги объекта: `blocking`, `waits_to_open`, `pickable`.
- **Ворота** (`objects.<kind>.waits_to_open: N`): непроходимы, пока герой не сделает `hero.wait()` N раз подряд (или `hero.wait(N)`), стоя на соседней клетке (расстояние по манхэттену = 1). Любой шаг, даже в стену, обнуляет счёт. Открытые — навсегда. Ребёнок видит на воротах число оставшихся ходов.
- **Предметы** (`objects.<kind>.pickable: true`): лежат на клетке, `hero.take()` поднимает предмет с клетки, где стоит герой (событие `pickup`, один тик). Пустая клетка — событие `nothing_to_take`, тоже тик. Поднятые `coin` считаются в `hero.coins`. Радиус — своя клетка.
- **Подделки** (`objects.<kind>.fake: {count: N, damage: D}`, только у `pickable`): N экземпляров — фальшивые, какие именно — случайно от `seed` прогона (браузер даёт новый seed на каждый запуск, так что выучить их нельзя). С виду одинаковые. `hero.check_coin()` — бесплатный запрос (ни тика, ни энергии): `True`, если предмет под ногами настоящий; `False`, если подделка или клетка пуста. После проверки подделка на сцене зеленеет, настоящая получает галочку. Поднятая подделка бьёт на D жизни (событие `hit`), в сумку не идёт, для `collect` не нужна. Схема требует `count` меньше числа экземпляров на карте.
- **Смерть**: hp ≤ 0 → событие `died`, программа обрывается, исход `lose/died`. Пока единственный источник урона — подделки (`hp_max` 20, `damage: 10` — две ошибки насмерть).
- **Преграды**: `objects.<kind>.jumpable: true` (яма) или `crawlable: true` (паутина) — непроходимы шагом (`blocked`, `into: <kind>`), `blocking` писать не надо. `hero.jump("right")` / `hero.crawl("right")` переносят героя через клетку преграды на следующую за ней: один тик, одна энергия, событие `jump`/`crawl`. Прыгать/ползти надо **с соседней клетки**. Не та преграда, пустая клетка или занятое приземление — `cannot_jump`/`cannot_crawl` с `into`, ход потрачен. Направление — строка `"right"|"left"|"up"|"down"`, иное — человеческая ошибка.
- **Запертые ворота** (`objects.<kind>.password: "слово"`): непроходимы, пока герой вплотную не скажет слово — `hero.say(x)` (тик есть, энергии нет; произносит `str(x)`, на сцене пузырь над головой — так видно значение переменной). Событие `say` с `opened` — какие ворота открылись. Открытые — навсегда. На решётке замок вместо числа. С `waits_to_open` не сочетается. `password` может быть списком (минимум два разных слова) — одно выбирается при запуске от seed; тогда слово кладут на **свиток**: `objects.<kind>: {pickable: true, reveals: <вид ворот>}` (символ `S`, рисуется пергаментом), и `hero.take()` на нём возвращает слово (на обычных предметах — `True`). Так `password = hero.take()` становится необходимым. `blank: {count: N}` у свитка — N из них пустые (какие — seed, схема требует N меньше числа свитков): `take` вернёт `""`. **Числа**: `gives: [7, 8, 9]` у предмета (без `reveals`) — `take` вернёт одно из них (одно на вид, от seed); `icon: coin|scroll|sack` — как рисовать (по умолчанию монетка, свиток с `reveals` — свиток). Число — своё у каждого экземпляра (в пределах вида разные, пока хватает списка). Пароль можно вычислить: `password: {subtract: [bag, note]}` — разность (сумм по виду) строкой, `{max: bag}` — наибольшее; `hero.say(число)` сравнивается как `str`. `hero.look()` — бесплатный запрос: то, что вернул бы `take()` (число/слово/`True`, `False` на пустой клетке), предмет остаётся; на сцене пузырь-мысль. `heavy: true` — в руках один такой предмет, второй `take` → событие `hands_full`, ход потрачен.
- **Завалы**: обычный `blocking: true` объект (`rubble`, символ `R`), рисуется горкой камней; смысл в нём только вместе со случайностью.
- **Случайные преграды и завалы**: `chance: 0.5` (0 < chance < 1, у преград и `blocking`-объектов; каждый экземпляр сам по себе) или `present: {count: N}` (на месте ровно N экземпляров из всех на карте — «открыт ровно один выход»; схема требует N меньше числа экземпляров; с `chance` не сочетается) — при запуске преграда на месте с такой вероятностью (от seed). Отсутствующая — обычный пол. В снимке `tiles` преграды идут со `state: present|absent`; лог несёт `initial` — снимок до первой команды, по нему сцена прячет отсутствующие сразу. Ребёнок узнаёт правду через `hero.can_move("right")` — бесплатный запрос «можно ли шагнуть» (событие `check_move`, на сцене ✓/✗ в углу клетки). Обход: `if hero.can_move("right"): hero.move_right(2) else: hero.jump("right")` — обе ветки кончаются на одной клетке.
- Реализованные команды: `hero.move_right/left/up/down(n=1)` (возвращают `True/False`), `hero.wait(n=1)`, `hero.take()`, `hero.check_coin()`, `hero.can_move(dir)`, `hero.jump(dir)`, `hero.crawl(dir)`, `hero.say(x)`, `hero.look()`. Всё остальное (`attack`, `nearest_enemy`, `open`, `pull`, юниты, генератор) — только в архитектурном документе, в схеме ключа `units` нет, `Hero` ответит «пока не реализована». В уровни не класть.
- `api` — белый список: команда вне списка → «У героя на этом уровне нет команды …». Только имена вида `hero.<команда>`. Из него же собираются боковой справочник и автодополнение в редакторе (подписи — `frontend/src/engine/commands.ts`; новая команда → добавить подпись туда).
- Победа проверяется **в конце программы**: все `goals` выполнены. Цели: `reach: [x, y]` (герой стоит здесь), `collect: <kind>` (все настоящие предметы этого вида подобраны; схема требует, чтобы вид был `pickable` и лежал на карте), `stay_alive: true` (hp > 0; смерть и так обрывает прогон, цель — для читаемости уровня). Причины проигрыша: `not_reached`, `not_collected`, `died` — тексты в `Play.tsx` (`LOSE_TEXT`). Исходы: `win` / `lose` / `error` (исключение) / `timeout` (бюджет 50 000 строк или 10 000 тиков).
- **Энергия**: `energy_max` 20; шаг (и упор в стену) и `take` стоят 1, `wait` возвращает 2 (не выше максимума). На нуле — событие `no_energy`, ход потрачен, действие не случилось. Эталон уровня должен укладываться с запасом: считать «действия − 2×wait ≤ ~14». Жизнь и урон в снимке есть, но пока ни на что не влияют (врагов нет).

## Скелет файла

```yaml
# Координаты: [x, y], начало в левом верхнем углу, y растёт вниз.
id: start-08            # ^[a-z0-9]+(-[a-z0-9]+)*$, = имя файла
lesson: 1               # ≥ 1
title: Короткое название
brief: >-
  Две-три фразы ребёнку на «ты»: что видно на карте и что сделать.

map:
  legend:               # все символы grid обязаны быть здесь; hero — ровно один
    "#": wall
    ".": floor
    "@": hero
    "|": gate
    ":": heavy_gate
    "o": coin
    "F": flag
  grid: |
    #######
    #@.|oF#
    #######

objects:                # только не-дефолтные виды
  gate:
    waits_to_open: 2
  heavy_gate:
    waits_to_open: 3
  coin:
    pickable: true

api:                    # ≥ 1, только hero.*; порядок = порядок в справочнике и автодополнении
  - hero.move_right
  - hero.wait

starter: |              # комментарий-намёк + начало; НЕ должен проходить уровень
  # Ворота открываются, если постоять рядом
  hero.move_right()

solution: |             # эталон; ОБЯЗАН проходить уровень; в браузер не уезжает
  hero.move_right()
  hero.wait()
  hero.wait()
  hero.move_right()
  hero.move_right()

goals:
  - reach: [5, 1]       # координаты флага
  - collect: coin       # если на карте есть предметы, которые нужно взять

medals:
  short: auto           # всегда так; медали пока нигде не считаются (в логе есть только metrics.ast_nodes)

hints:                  # after_fails ≥ 1; в браузер не уезжают и в UI пока не показываются — всё равно заполнять
  - after_fails: 1
    text: Направление — куда смотреть, что заметить.
  - after_fails: 2
    text: Диагноз типичной ошибки.
  - after_fails: 4
    text: Полный ответ словами («вправо, два раза wait, …»).
```

## Соглашения, которых держатся существующие уровни

- Символы legend фиксированы: `#` стена, `.` пол, `@` герой, `F` флаг, `|` ворота (`gate`), `:` тяжёлые ворота (`heavy_gate`), `o` монетка (`coin`), `P` яма (`pit`), `W` паутина (`web`), `R` завал (`rubble`), `D` запертая дверь (`door`, `password`), `S` свиток (`scroll`, `reveals`), `B` мешок (`bag`, `gives`, `icon: sack`). Новые виды — новый символ, но сначала спросить, реализован ли объект.
- Новый вид объекта на сцене надо нарисовать: `LevelScene.tsx` знает `flag`, ворота и предметы (монетка рисуется кодом); плитки `tools/tiles.py preview` различают только стену и не-стену.
- Одна новая идея на уровень. `api` расширяется ровно на то, что уровень учит; старые команды остаются.
- `brief` называет команду явно (`hero.move_right()`), когда она новая. `**слово**` в `brief` подсвечивается в UI — для пароля или числа, которое ребёнок переносит в код как есть.
- Карта маленькая: 5–9 в ширину, 3–5 в высоту; всё окружено `#`.
- Лестница подсказок: 1 → куда смотреть, 2 → типичная ошибка, 4 → готовый ответ словами.
- `starter` — приглашение писать, не половина решения.

## Что уже есть

Занятие 1, `start-*`: 01 три шага вправо · 02 назад (move_left) · 03 вверх (move_up/down) · 04 за угол (все четыре) · 05 змейка · 06 ворота + wait · 07 двое ворот (2 и 3 хода) · 08 монетка + take (цель collect) · 09 «Тайник»: коридор с монеткой + ответвление за воротами со второй, collect требует обе · 10 «Длинные коридоры»: 7 вправо, 2 вниз, 7 влево — аргумент `move_right(7)`.

Занятие 2 (условия), `if-*`: 01 «Фальшивые монеты» — коридор из пяти монет, две случайные подделки, `if hero.check_coin(): hero.take()` · 02 «Ямы и паутина» — статичная змейка, `jump`/`crawl` вправо и влево; в заготовке готовый блок `if hero.can_move(...): … else: …` как образец, ребёнок повторяет его · 03 «То ли яма, то ли нет» — та же конструкция, но яма и паутина с `chance: 0.5`, и без неё не пройти · 04 «Два тайника» — закрепление без новых идей: длинный коридор, два ответвления (ворота 2 и 3, яма/паутина, по монете, одна из двух фальшивая), `move_right(5)`, `jump("up")`/`crawl("down")` и обратно, `check_coin` · 05 «Обвал» — завал либо в коридоре, либо на входе в обход (`present: 1` из 2), `else` с телом в три строки · 06 «Перекрёсток» — три выхода, открыт один (`present: 2` из 3), три `if` подряд без `else`, все дороги к одному флагу, вход к флагу только слева, чтобы поздние проверки у флага были ложны.

Занятие 3 (переменные), `var-*`: 01 «Два пароля» — две двери с разными паролями (слова подсвечены в задании); первая переменная и `hero.say(password)` даны в заготовке как образец, вторую (`password2 = "фонарь"`) ребёнок делает сам · 02 «Свиток» — петляющий коридор, свиток со случайным паролем (`reveals`), `password = hero.take()` → `hero.say(password)` у двери · 03 «Пустой свиток» — два свитка, один случайно пустой (`blank`), две переменные и первое сравнение: `if first == "": say(second) else: say(first)` · 04 «Сторож» — мешок (`gives`, число монет) и свиток с числом «сколько донести», у двери `pay = coins - need; hero.say(pay)` — первая арифметика · 05 «Два мешка» — два тяжёлых мешка, `hero.look()` в оба, `if first > second:` с разными дорогами в ветках, `password: {max: bag}`.

Новый префикс id на новое занятие; в UI уровни всё равно нумеруются сквозняком по порядку `lesson`, потом `id`.

## Проверка перед сдачей

```bash
backend/.venv/Scripts/python tools/level_schema.py            # формат, понятный вывод
backend/.venv/Scripts/python -m pytest simulator/tests/test_levels.py -q   # solution проходит, starter — нет
backend/.venv/Scripts/python tools/tiles.py preview dungeon <каталог>       # PNG карт, показать пользователю
```

Тест `test_starter_does_not_win` падает, если заготовка сама доходит до флага. Тест `test_solution_wins` — если эталон не проходит (проверить `reach` против позиции `F` в grid: считать x от 0 по строке, y — номер строки). Оба гоняются на дюжине seed — уровень с подделками эталон обязан проходить при любом раскладе.
